Migration Guide · Existing Plugins Only

bpl-tools Dashboard
What Changed

This guide is for developers who already have a working bpl-tools dashboard and need to upgrade to the new version. It covers only the two files that changed — data.js and App.js.

Scope of this guide — only these two files:
  • src/admin/utils/data.js — new exports, new shape for welcomeInfo, changelog badge format
  • src/admin/Components/App.js — new route pattern, updated Welcome spread
Everything else (PHP, webpack, CSS variables, blocks.js) is unchanged from before.
Reference plugin advanced-post-block-pro Version 1.0 · May 2026

Summary of Changes

  • Modified data.js — welcomeInfo() is now a separate named export (was inline inside dashboardInfo)
  • New data.js — welcomeInfo adds gettingStarted tabs structure, keywords, keywordsLabel
  • New data.js — changelogs array moved into welcomeInfo with badge-ready <strong> prefixes on every list item
  • New data.js — changelogsLimit and changelogsReadMoreLabel props
  • New data.js — proFeatures array moved into welcomeInfo
  • Modified App.js — Welcome now receives {...welcomeInfo(adminUrl)} spread in addition to base props
  • Modified App.js — Demos now takes demoInfo={demoInfo} prop (not spread)

Part 1 — data.js

1A. dashboardInfo — what to check

dashboardInfo itself is largely the same. Verify these fields are present:

Field Status Note
startButton New { label: 'Start Now', url: '...' } — primary CTA button in hero
deleteDataOnUninstall New (optional) Pass from PHP localize if your plugin has a Settings page with cleanup
uninstallNonce New (optional) Required alongside deleteDataOnUninstall
name / slug / media / pages / freemius Unchanged No changes needed

1B. welcomeInfo — extract into its own export

In the old dashboard, welcome-specific data (changelogs, proFeatures) lived directly inside dashboardInfo. Now they live in a separate welcomeInfo(adminUrl) export and are spread onto <Welcome> in App.js.

The key structural change: welcomeInfo is now called with adminUrl so it can build dynamic URLs for the Getting Started step links. Always export it as a function, not a plain object.

Full welcomeInfo structure

1C. Changelog list items — badge prefix format

The Changelog component automatically converts the leading <strong> tag into a colored pill badge. Every list item must be prefixed. Here is the mapping:

<strong> text Badge rendered Color
New, Add New Primary color (CSS var)
Update Update Orange #FF8D28
Fix, Fixing, Fixed, Remove Fix Red #FF383C
Improve, Improvement Improvement Purple #8b5cf6
Anything else Other Gray #9ca3af
Colons are stripped automatically. Write <strong>Fix:</strong> and the badge will display as "Fix" (no colon). The colon is conventional and cleaned up by the component.

Before / After example

// ✗ Old format (no badge rendered)
'Fix: Resolved pagination issue'

// ✓ New format (renders a Fix badge in red)
'<strong>Fix:</strong> Resolved pagination issue'

Full before/after for a real changelog entry

// ✗ Before — no badges
{

	type:		'update',
	list: [
		'ShortCode feature for free users.',
		'Admin Dashboard - Improved UI.',
		'Critical performance improvements.'
	]
}

// ✓ After — all items prefixed with <strong>Type:</strong>
{
	version: '2.0.5 - 22 Feb 2026',
	type:		'update',

Part 2 — App.js

Two changes are required in App.js:

  • New Import welcomeInfo from data.js and spread it onto <Welcome>
  • Modified <Demos> takes demoInfo={demoInfo} as a named prop (not spread)

2A. Import welcomeInfo

// ✗ Before
import { demoInfo, pricingInfo, settingsInfo } from '../utils/data';

// ✓ After — add welcomeInfo to the import
import { demoInfo, pricingInfo, settingsInfo, welcomeInfo } from '../utils/data';

2B. Spread welcomeInfo onto Welcome

// ✗ Before — Welcome only received base props
<Route path='welcome' element={<Welcome {...props} />} />

// ✓ After — also spread welcomeInfo(adminUrl)
<Route path='welcome' element={<Welcome {...props} {...welcomeInfo(adminUrl)} />} />

// Do the same for the index route:
<Route index element={<Welcome {...props} {...welcomeInfo(adminUrl)} />} />
Why both spreads are needed: props contains base plugin info (name, slug, media, etc.) from dashboardInfo. welcomeInfo(adminUrl) adds the welcome-only props (gettingStarted, changelogs, proFeatures etc.). The Welcome component requires all of them.

2C. Demos prop change

// ✗ Before (spread)
<Route path='demos' element={<Demos {...props} {...demoInfo} />} />

// ✓ After (named prop)
<Route path='demos' element={<Demos {...props} demoInfo={demoInfo} />} />

2D. Full App.js after changes

Complete final file for reference:

import { HashRouter as Router, Routes, Route, Navigate } from 'react-router-dom';

import Welcome			 from '../../../../bpl-tools/Admin/Welcome';
import Demos				 from '../../../../bpl-tools/Admin/Demos';
import Pricing			 from '../../../../bpl-tools/Admin/Pricing';
import FeatureCompare from '../../../../bpl-tools/Admin/FeatureCompare';
import Activation		from '../../../../bpl-tools/Admin/Activation';
import OurPlugins		from '../../../../bpl-tools/Admin/OurPlugins';
import { Settings }	from '../../../../bpl-tools/Admin';

import Layout from './Layout';
import { demoInfo, pricingInfo, settingsInfo, welcomeInfo } from '../utils/data';	// ← added welcomeInfo

const App = (props) => {
	const { isPremium, adminUrl } = props;

	return <Router>
		<Routes>
			<Route path='/' element={<Layout {...props} />}>

				/* ← spread welcomeInfo on both index and welcome routes */
				<Route index	 element={<Welcome {...props} {...welcomeInfo(adminUrl)} />} />
				<Route path='welcome' element={<Welcome {...props} {...welcomeInfo(adminUrl)} />} />

				/* ← demoInfo as named prop, not spread */
				<Route path='demos' element={<Demos {...props} demoInfo={demoInfo} />} />

				{!isPremium && <Route path='pricing'
					element={<Pricing pricingInfo={pricingInfo} options={{}} {...props} />} />}

				{!isPremium && <Route path='feature-comparison'
					element={<FeatureCompare plans={['free', 'pro']} {...props} />} />}

				<Route path='activation'	element={<Activation {...props} />} />
				<Route path='settings'		element={<Settings {...props} {...settingsInfo} />} />
				<Route path='our-plugins' element={<OurPlugins {...props} />} />

				<Route path='*' element={<Navigate to='/welcome' replace />} />
			</Route>
		</Routes>
	</Router>;
};
export default App;

How the badge injection works (reference)

You don't need to modify any bpl-tools files. The logic is in bpl-tools/Admin/Welcome/Changelog/index.js. It processes each list item HTML string before rendering: 

// Automatically applied to every item — no changes needed in bpl-tools
const BADGE_MAP = {
	new: 'new', add: 'new',
	update: 'update',
	improve: 'improvement', improvement: 'improvement',
	fix: 'fix', fixing: 'fix', fixed: 'fix', remove: 'fix',
};

const processItem = (html) => html.replace(
	/^<strong>([^<]+)<\/strong>/i,
	(_, label) => {
		const clean = label.replace(':', '').trim();
		const cls	 = BADGE_MAP[clean.toLowerCase()] || 'default';
		return `<strong class="changelogBadge ${cls}">${clean}</strong>`;
	}
);

Your only responsibility is to ensure the list item string starts with <strong>TypeWord:</strong>. The component handles the rest.
